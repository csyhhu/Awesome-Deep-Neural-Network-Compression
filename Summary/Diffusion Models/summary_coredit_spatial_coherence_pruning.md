## 综合理解（用户笔记）
本文做DiT模型的Token Pruning. 具体来说：将Token拆分成多个子网络，计算每个子网络内的Token和子网络平均值的余弦相似度，得到Token重要性。相似度越高表示该Token越能被重构，因此重要性越低，越能跳过。并通过渐进地改变某个子网络和推理时间的剪枝率。

### 点评：理解基本正确，但有 5 处需修正

1. **"子网络"应为"子网格 (sub-grid)"**：论文是将 token 的**空间网格**划分为不重叠的 $w \times w$ 子网格，这是对 token lattice 的空间划分，不是神经网络意义上的"子网络"。

2. **"得到 Token 重要性"应为"得到 Token 冗余度"**：SC（空间一致性）衡量的是 token 的**冗余程度**，而非传统意义上的"重要性"。方向与传统 token pruning 相反：传统方法剪掉重要性**低**的 token，而本文剪掉 SC **高**（冗余度高）的 token。

3. **重建的因果关系需修正**：您说"相似度越高表示越能被重构，因此重要性越低"——因果关系略反。准确说法是：SC 高 = token 与邻域**高度相似（冗余）**，所以它既是**跳过**的好候选，也是**重建**的好对象。重建之所以可行，正是因为被剪 token 与邻域保留 token 相似，而非"能被重构所以才剪"。

4. **"渐进地改变某个子网络和推理时间的剪枝率"术语与机制需澄清**：
   - 是"块 (block)"而非"子网络"——剪枝预算分配到 Transformer 块，不是子网格。
   - 涉及两个方向相反的机制：**微调期**渐进**增加**剪枝率（progressive pruning，$\Delta R_l$ 决策加到哪个块）；**推理期**时间步两阶段衰减在后期**减少**剪枝率（$c=0.25$）。不能笼统称为"渐进改变"。

5. **遗漏了重建组件的核心地位**：CoReDiT 是"Pruning **and Reconstruction**"双组件框架，重建不是附属品而是核心贡献之一。单纯跳过会破坏空间连续性导致伪影，重建是保持生成质量的关键。

**总评**：您抓住了核心思路（SC 选择冗余 token + 自适应剪枝调度），方向正确；主要偏差在术语精度（子网络/重要性）和机制完整性（重建、两个调度方向）。修正上述 5 点后即为准确概括。

## 一、研究动机

Diffusion Transformers (DiTs) 以 Transformer 块替换了传统 U-Net，凭借对长程依赖的建模能力和对多模态条件的灵活支持，在图像/视频生成任务上取得了 SOTA 结果。然而，DiT 的自注意力计算量随 token 数呈二次方增长，在高分辨率图像和多帧视频场景下计算与显存开销巨大，严重制约了云端与移动端部署。

经验观察表明：DiT 中存在大量**视觉冗余 token**（如均匀背景、平滑纹理区域），它们与空间邻域高度相似，存在显著的加速空间。但将已有 ViT 中的 token 剪枝方法直接迁移到 DiT 面临三大挑战：

1. **如何高效定位低显著度 token**：传统基于注意力分数的重要性判别需要构造 $N \times N$ 注意力矩阵，二次复杂度抵消了剪枝收益。
2. **如何保持被剪枝 token 的视觉语义**：生成式 DiT 对空间连续性要求高，直接丢弃 token 会引入纹理断裂、边界伪影。
3. **如何确定剪枝调度**：不同 Transformer 块、不同去噪时间步的冗余度不同，均匀剪枝并非最优。

## 二、方法概述

CoReDiT 是一种**训练后（post-training）**的结构化 token 剪枝框架，仅作用于自注意力模块，通过轻量微调学习块自适应的剪枝调度。核心由三个组件构成：

### 2.1 基于空间一致性的 Token 选择 (Spatial Coherence Selection)

**核心观察**：低显著度 token 通常具有强局部冗余——其特征与空间相邻 token 高度相似。

**空间一致性 (Spatial Coherence, SC) 分数**：将 token 网格划分为不重叠的 $w \times w$ 子网格 $\mathcal{G}(i)$，对 token $x_i$ 定义其与同网格内所有 token 的平均余弦相似度：

$$\text{SC}(x_i) := \frac{1}{|\mathcal{G}(i)|}\sum_{j \in \mathcal{G}(i)} \text{sim}(x_i, x_j)$$

**线性时间高效计算**：利用归一化技巧，SC 可简化为 token 归一化嵌入与网格均值归一化嵌入的内积：

$$\text{SC}(x_i) = \hat{x_i}^T \hat{g_i}$$

其中 $\hat{g_i}$ 为同网格内归一化嵌入的均值。该计算只需每网格一次规约 + 每 token 一次点积，复杂度为 $O(N)$，与网格大小 $w$ 无关，硬件友好。

**选择规则**：SC 越高表示该 token 越可由邻域解释（越冗余），因此跳过 SC 最高的前 $K = r(l,s) \cdot N$ 个 token（$r(l,s)$ 为块 $l$、时间步 $s$ 的剪枝率），仅保留 $X_R$ 参与全局自注意力计算。

可视化显示：高 SC token 集中在背景区域，边界/纹理处 SC 较低，符合直觉。

### 2.2 基于一致性的 Token 重建 (Coherence-based Reconstruction)

**动机**：直接跳过 token 会破坏空间连续性，导致生成伪影。需要从保留 token 重建被跳过 token 的注意力输出，以保持后续块的密集网格。

**重建公式**：对被跳过的 $x_i \in X_S$，用局部邻域内保留 token 的注意力输出做相似度加权聚合：

$$y_i = \frac{\sum_{j \in \mathcal{S}(i)} \text{sim}(x_i, x_j)\, y_j}{\sum_{k \in \mathcal{S}(i)} \text{sim}(x_i, x_k)}$$

其中 $\mathcal{S}(i)$ 为 $x_i$ 局部邻域内的保留 token。

**SC 近似相似度**：由于被跳过的是高 SC token（$\hat{x_i} \approx \hat{g_i}$），可证明 $\text{sim}(x_i, x_j) = \text{SC}(x_j) + O(\epsilon_i)$，其中 $\epsilon_i = \|\hat{x_i} - \hat{g_i}\|$ 很小。因此用 $\text{SC}(x_j)$ 近似相似度权重，避免了成对相似度计算：

$$y_i \approx \frac{\sum_{j \in \mathcal{S}(i)} \text{SC}(x_j)\, y_j}{\sum_{k \in \mathcal{S}(i)} \text{SC}(x_k)}$$

**子网格设计**：将每个 $w \times w$ 网格进一步细分为更小的 $w_s \times w_s$ 子网格（如 $3 \times 3$），限制聚合范围，避免过度平滑，同时保持 $O(N)$ 复杂度。注意：局部性仅用于选择与重建，保留 token 之间的注意力仍是全局的，不改变注意力模式。

**两个微设计**：
- **交替网格大小**：固定网格边界会引入边界伪影，跨块交替网格大小（如 $16 \times 16$ 与 $9 \times 9$ 交替）使边界偏移，信息可跨网格传播。
- **$m$-stride 保留**：高冗余区域可能整个子网格被跳过，导致无重建锚点。强制每个 $m$ 位置保留至少一个 token（$m \le w_s$）：对块 $l$，保留满足 $(i+j-l) \bmod m = 0$ 的 token（通过减去大偏移使其 SC 不被选中）。

### 2.3 渐进式、块自适应剪枝调度 (Progressive Block-Adaptive Pruning)

**动机**：Token 冗余度随去噪时间步和 Transformer 块位置变化——早期时间步噪声主导、建立全局语义（冗余多），后期时间步细化局部细节（冗余少）；不同块的局部性也不同。均匀剪枝非最优，且骤加大剪枝率难以恢复。

**基于一致性的渐进式剪枝**：微调中每 $T$ 步给选中块增加 $\Delta k$ 个剪枝 token，直到达到目标预算。选择下一个增量块的依据为该块**下一批**候选 token 的冗余度：

$$\Delta R_l = \sum_{i=K(l,s)+1}^{K(l,s)+\Delta k}\text{SC}_i^l$$

每 $T$ 步将下一个 $\Delta k$ 分配给 $\Delta R_l$ 最大的块（即下一批待剪 token 最冗余的块），自动将预算分配给最冗余的块。

**时间步两阶段衰减**：早期时间步激进剪枝，后期时间步减小剪枝率。采用轻量两阶段衰减（仅需每块两个计算图，便于移动端部署）：

$$r(l, s) = \begin{cases} r(l), & 1 \le s \le s_0 \\ c \cdot r(l), & s_0 < s \le S \end{cases}$$

其中 $0 < c < 1$ 为后期衰减系数。

**经验验证**：在 PixArt-$\alpha$-1024 上，块间初始冗余度差异显著，学习到的调度将更高剪枝率分配给持续冗余的块，而低冗余块（如 5、7 块）保持低剪枝率，快速降低 FLOPs 同时维持生成质量。

## 三、实验设置

- **模型**：PixArt-$\alpha$-1024（文本生成图像）、PixArt-$\Sigma$-2048（高分辨率）、MagicDrive-V2（自动驾驶视频生成）。
- **微调数据**：CLEAR 10K 合成数据集（FLUX.1-dev 生成）；MagicDrive-V2 在 nuScenes 上微调。
- **剪枝配置**：每 $T=15$ 步增加 $\Delta k=64$ token，块级剪枝率上限 60%；两阶段时间步衰减 $c=0.25$，最后 5 步衰减。
- **蒸馏损失**：$L_{distill} = L_{ori} + \alpha L_{pred} + \beta L_{attn}$（$\alpha=\beta=0.5$，遵循 CLEAR）。
- **评估指标**：图像用 FID/CLIP/IS；视频用 FVD/LPIPS/PSNR/SSIM 及 BEVFormer 条件对齐（mAP/mIoU）。

| 实验 | FID↓ | CLIP↑ | IS↑ |
|------|------|-------|-----|
| 基线 | 27.3 | 31.6 | 37.77 |
| **CoReDiT (r=45%)** | 28.5 | 31.9 | 36.65 |

关键发现：

3. **渐进式剪枝优于均匀剪枝**：渐进式块自适应调度（FID 28.5）显著优于均匀 50% 剪枝后微调（FID 32.3）。

## 六、总结与未来工作

CoReDiT 提出以**空间一致性**作为 DiT 中局部冗余的实用信号，结合高效线性时间选择、一致性引导重建和渐进式块自适应调度，在图像与视频生成任务上实现了：

- 最高 **55% 自注意力 FLOPs 降低**；
- 云端 GPU **1.33×**、移动端 NPU **1.72×** 推理加速；
- 保持高视觉质量与条件对齐，并提供显存余量支持更高分辨率生成。

**未来工作**：
1. 将效率扩展到 FFN/MLP 组件，进一步降低非注意力开销；
2. 引入跨帧一致性目标和显式建模时序冗余的剪枝策略，改善视频时序一致性（FVD）。

## 七、与相关工作的定位区别

- 区别于**跨时间步缓存方法**（FasterCache/ToCa）：CoReDiT 聚焦时间步内冗余。
- 区别于**动态路由方法**（FlexDiT/DiffCR）：无需引入可学习路由模块，SC 为无需学习的冗余信号。
- 区别于**Token 合并方法**（ToMe）：不进行合并/解合并，而是跳过并重建，保留完整 token 网格。
- 区别于**纯训练自由方案**：通过轻量微调学习块/时间步特定剪枝调度，优化硬件相关的速度-质量权衡。

## 八、讨论与问答

### Q1：ViT 中的 token pruning 方法有哪些，Related Work 中提到哪些？

论文 Related Work 第2节将 DiT 中的 token reduction 方法归为五类，其中**直接相关的 token pruning/merging 方法**集中在第一类：

**(1) 时间步内 token 减少（Token reduction within a timestep）**，又可细分为：
- **训练自由（Training-free）**：
  - **ToMe** (Bolya et al. 2022)：Token Merging，基于相似度合并 token
  - **ToMA** (Lu et al. 2025)：DiT 专用的 token 合并变体，旨在减少合并开销
  - **ToDo** (Smith et al. 2024)：仅下采样 Key/Value token，而非合并 Query
- **学习-based（Learning-based）**：
  - **DiffCR** (You et al. 2025)：用可微分压缩比例学习每层/每时间步的 keep ratio 或 token router
  - **FlexDiT** (Chang et al. 2024)：动态 token 密度方案

此外，Related Work 末尾草稿段落更明确地把 ViT 中的 token pruning 信号归为三类：
1. **基于注意力分数的显著性**（Kim et al. 2022 的 Learnable Token Pruning、Singh et al. 2024 的 ToSA）
2. **基于特征相似度**（ToMe）
3. **基于可学习预测器**（DynamicViT, Rao et al. 2021；DiffCR, You et al. 2025）

Related Work 还提到几个**正交方向**（非 token pruning 但相关）：
- **(2) 跨时间步缓存与特征复用**：DeepCache、FasterCache、ToCa（token-wise caching）、ClusCa（cluster-driven）、CAT Pruning（混合方案）
- **(3) 动态计算与条件路由**：DyDiT（时间步动态宽度+空间跳过）、DiffCR、FlexDiT
- **(4) 稀疏/结构化注意力核**：Sparse VideoGen（profiling-based）、VSA（可学习稀疏注意力）
- **(5) 权重剪枝与架构编辑**：DiffPruning（结构化剪枝）、grafting（架构编辑）

**CoReDiT 的定位**：post-training、时间步内、结构化 token skipping + 重建，不引入可学习路由，与上述方法正交或可组合。

### Q2：SC 的计算、时间相似性、观察结论与重建 motivation

**(a) SC 衡量的是"冗余度"而非"重要性"**
传统 token pruning 用重要性分数，剪掉分数**低**的 token。而本文 SC 分数**越高**，说明该 token 越能被邻域解释（越冗余），越应该被剪掉——这是与传统重要性逻辑相反的设计。因此准确表述应为"SC 衡量 token 的冗余度"，而非"重要性"。

**(b) SC 是纯空间的，不涉及时间维度**
SC 在**单个时间步内**计算，基于同一空间网格内 token 的余弦相似度。论文**没有计算"时间上的相似性"**。论文在 2.3 节通过 Figure 展示了 SC 随去噪时间步**演化**的现象（早期时间步 SC 普遍高→噪声主导粗结构；中期背景冗余突出；后期边缘细节 SC 低），但这只是观察统计，SC 本身的计算公式不含任何时间项。

**(c) 观察结论修正**
高 SC token 集中在**低显著度区域（如均匀背景、平滑纹理）**，而**边界/纹理/物体轮廓**处 SC 较低。即高 SC ≈ 背景冗余，低 SC ≈ 关键语义/细节。（注：原问题中"边缘区域"应为"背景区域"的笔误。）

**(d) 重建 motivation**
正因为被跳过的是**高 SC（冗余）token**，它们与邻域保留 token 高度相似，所以特别适合用邻域保留 token 的注意力输出做加权聚合重建——这正是 2.2 节"基于一致性的重建"的核心 motivation。论文还给出理论近似：$\text{sim}(x_i,x_j) = \text{SC}(x_j) + O(\epsilon_i)$，因为被剪 token 的 $\epsilon_i = \|\hat{x_i}-\hat{g_i}\|$ 很小，所以可用 $\text{SC}(x_j)$ 近似相似度权重，避免成对相似度计算。

### Q3：2.3 中公式与 progressive pruning 的关系——区分两个"渐进"维度

论文有**两个不同维度**的剪枝调度机制，容易混淆：

**(a) 微调过程中的渐进式剪枝（Progressive pruning during fine-tuning）——这才是"逐渐增加"的那个**

公式：
$$\Delta R_l = \sum_{i=K(l,s)+1}^{K(l,s)+\Delta k}\text{SC}_i^l$$

这个公式**不是直接调整剪枝数量**，而是一个**决策信号**：每 $T$ 步，计算块 $l$ 下一批 $\Delta k$ 个候选 token 的 SC 之和（即下一批待剪 token 的冗余度），然后把下一个 $\Delta k$ 的剪枝增量分配给 $\Delta R_l$ 最大的块。

**实际的"逐渐增加"行为**是：微调中每 $T$ 步给选中块的 $K(l,s)$ 增加 $\Delta k$（即 $r(l,s)$ 逐渐增大），直到达到目标预算。所以是**微调训练迭代层面**的渐进增加，目的是避免骤加大剪枝率导致难以恢复。

**(b) 推理时的时间步两阶段衰减（Timestep-wise decay）——这个是"后期减少"**

公式：
$$r(l, s) = \begin{cases} r(l), & 1 \le s \le s_0 \\ c \cdot r(l), & s_0 < s \le S \end{cases}$$

这是**推理时去噪时间步层面**的调度：早期时间步用完整剪枝率 $r(l)$，最后 $S-s_0$ 步衰减为 $c\cdot r(l)$（$c=0.25$）。即**后期减少剪枝**，而非增加——因为后期时间步细化细节，冗余度低，需要保留更多 token。

**对原问题的直接回答**：
- 如果问的是"微调过程中剪枝 token 数是否逐渐增加"→ **是的**，由 progressive pruning 机制实现，$\Delta R_l$ 公式负责决定加到哪个块。
- 如果问的是"推理时随 diffusion 去噪渐进剪枝是否增加"→ **不是**，恰恰相反，后期时间步会衰减（减少）剪枝率。

这两个机制共同作用：微调中逐块渐进增加总剪枝量（训练期）+ 推理时按时间步两阶段衰减（推理期），最终得到块自适应、时间步自适应的剪枝调度。
