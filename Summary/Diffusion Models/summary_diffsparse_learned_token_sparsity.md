## 🧠 综合理解（讨论后修正版）

本文提出一种**可学习的分层稀疏分配**方法（**不是**新的 token importance metric）。核心是一个轻量**代价预测器 C**（`T×L×|S|` 参数表，约数千参数），学习每个 (去噪步 t, 层 l) 在不同候选稀疏率 s 下的**代理代价（surrogate cost）**；**动态规划**在全局压缩约束 R 下从 C 求最优分配——每层每步保留多少 token 重算；**token 选择器**（沿用 ToCa/DuCa 已有 importance score）按分数决定**哪些** token 重算。

被**缓存**的 token（非"删除"）在 `<t,l>` 自身不更新（输出用旧缓存值），但仍作为 self-attention 的 K/V 影响其他 token；其缓存值是**最近一次被重算时**的特征（可能跨多步，非仅 `<t-1,l>`），沿层向前传播直到被重算刷新。训练用 **STE** 打通离散 mask 的梯度，**LPIPS 蒸馏**（teacher=原模型，student=冻结权重+动态缓存）端到端优化 C，**两阶段 + warm-start** 消除 full-step 依赖。推理时 DP 不运行，用预计算 mask。

### 评价与关键澄清

1. **最大误区纠正**：本文贡献**不是**"提出 token pruning metric"，而是"学习稀疏分配（学多少）"。metric 沿用已有工作（attention/similarity/norm 均可），本文明确"does not introduce a new token-selector"。C 的增益**跨 metric 一致**（Table 4），证明"学多少"与"学哪些"正交。

2. **"loss 状态方程"是直觉非严格**：C 是经 LPIPS 端到端优化出的**代理代价**，非真实 loss 值，无闭式表达。直觉上可视为"状态图"，但严格说是 surrogate。

3. **"pruning"应为"caching"**：token 不被删除，是复用缓存特征（feature caching），与 token dropping（如 DyDiT）是不同技术。

4. **"复用 `<t-1,l>`"不严格**：缓存 token 复用的是**最近一次被重算时**的特征，若连续多步被缓存，则跨多步复用同一旧值（这正是 `s₃` cache-reuse frequency 监控的对象）。

5. **训练数据**：仅 10,000 个 captions/class indices（**不用图像**），不与评测集重叠。

## 🎯 研究动机与问题

### 背景：扩散 Transformer 与特征缓存

- **扩散 Transformer (DiT)**：输入为 token 集合 `X ∈ ℝ^{N×D}`，由 `L` 个 block 堆叠，每个 block 含 self-attention (SA)、cross-attention (CA)、MLP。多步去噪中反复评估噪声预测网络，FLOPs 占主导。
- **特征缓存**：相邻 timestep 特征高度相似，存在大量冗余。Token 级缓存（如 ToCa）比层级缓存粒度更细，加速更好。

### Token 级缓存的两大缺陷

| 缺陷 | 描述 | 后果 |
|------|------|------|
| **手工稀疏分配** | 每层每步需手动设定 reuse 比例 `R`，参数空间 `(L×T)` 巨大 | 难调、不scalable、次优 |
| **依赖 full-step** | 保留若干步全量前向计算以纠正误差（如 FORA、ToCa） | 削弱 token 级缓存的加速潜力 |

**Token 缓存机制回顾**（公式 3、4）：

```
对每层 f，每个 token x̂_i：
  F(x̂_i) = γ_i · f(x̂_i) + (1-γ_i) · C(x̂_i)
  其中 γ_i = 0 (缓存复用) 或 γ_i = 1 (重新计算)
  被重算的 token 同步更新缓存：C(x̂_i) ← F(x̂_i)
```

### 目标

用一个**可学习、端到端**的框架，自动决定所有层和所有步的最优稀疏配置，并**移除对预定义 full-step 的依赖**。

## 💡 方法：DiffSparse 框架

DiffSparse 由三个组件构成（见 Figure 1）：token 选择器、稀疏代价预测器、动态规划求解器。

### 1. Token 选择器（公式 5）

为每个 token 计算复合重要性分数：

```
S(x̂_i) = B( Σ_q λ_q · s_q(x̂_i) )
```

包含四个准则（详见附录）：

| 分量 | 含义 | 作用 |
|------|------|------|
| `s₁` (self-attention influence) | `Σ_j α_ij`，token 对他人的注意力贡献 | 影响大者误差易传播，需重算 |
| `s₂` (cross-attention focus) | 交叉注意力权重的**负熵** `-Σ_j o_ij log o_ij` | 聚焦度高的 token 受文本控制强，需重算 |
| `s₃` (cache-reuse frequency) | `n_i`，自上次计算以来被复用的次数 | 复用多→累积误差大→需重算 |
| `B` (spatial bonus) | `k×k` 邻域内最高分者加 `λ₄` | 促进被选 token 空间均匀分布 |

按分数降序取 top-K（K 由稀疏率 R 决定）。**注意：token 排序策略与本文贡献正交**，DiffSparse 的分配方案对不同排序方法均有一致增益（Table 4）。

### 2. 可学习稀疏代价预测器

- **候选集** `S`：例如 `N=256`，步长 32 → `S={0, 0.25, 0.5, 0.75, 1.0}`，`|S|=5`（对应保留 {0,64,128,192,256} 个 token）。
- **参数**：`(T×L) × |S|` 个可学习参数，输出归一化代价矩阵 `C ∈ ℝ^{(T×L)×|S|}`。
- **关键性质**：尺寸只依赖 `T, L, |S|`，**与 token 序列长度 N 无关** → 可跨分辨率迁移。
- **目标**：最小化累计代价，同时满足全局稀疏率 `R`。

### 3. 动态规划求解器（公式 6、7）

在全局稀疏约束下求最优分配：

```
状态：F(l̂, r) = 前 l̂ 层、总稀疏为 r 时的最小累计代价
转移：F(l̂, r) = min_{s∈S, s≤r} [ F(l̂-1, r-s) + C_{l̂, s} ]
回溯：重构最优稀疏分配
```

- 时间复杂度 `O((L·T)²·|S|)`，配合预剪枝策略可行。
- **DP 仅在训练时运行**（约 30 秒），推理时直接用预计算 mask，**零推理开销**。
- 用 **Straight-Through Estimator (STE)** 近似离散 mask 对代价预测的梯度，实现端到端优化。

### 4. 训练损失：LPIPS 感知蒸馏

```
L_LPIPS = LPIPS(x₀, x₀')
```

- 教师 = 原始全量模型（梯度 detach），学生 = 剪枝模型。
- 多步采样后比较输出，梯度只回传给学生。
- LPIPS 在学习到的感知特征空间度量，优于 L2（过平滑）和 SSIM（空间过惩罚）（Table 5）。

### 5. 两阶段训练策略（核心创新之一）

| 阶段 | 操作 | 目的 |
|------|------|------|
| **Stage 1** | 独立优化 step 代价矩阵 `C_f ∈ ℝ^{T×2}`（哪些步该 full）和层稀疏代价矩阵 `C_l ∈ ℝ^{(L×T)×|S|}`；DP 求 `|T_f|` 个最优 full-step 位置 | 先学 full-step 纠错位置 + 层稀疏代价初值 |
| **Stage 2** | 用 warm-start 把 `C_f` 注入 `C_l`：对选中 full-step 的 `s=N` 候选**减 δ**（公式 8）；微调统一代价矩阵 | 保留层间代价排序，同时允许 DP 自主决定是否真需 full 计算，**消除硬性 full-step 依赖** |

```
公式 (8)：  C_l^(t,l,N) ← C_l^(t,l,N) - δ,   ∀t∈T_f, l, s=N
```

`δ=10` 最优（Table 6）：`δ=0`（无 warm-start）明显变差，`δ` 过大则过度鼓励 full 计算。

## 📊 层稀疏性可视化分析（Figure 3）

PixArt-α 256×256，20 步，1.74× 加速下的学习到的稀疏分配：

- **Self-attention**：早期步 + 浅层稀疏更高（更可缓存）。
- **Cross-attention**：后期步 + 深层稀疏更低 → **文本语义在初始层最重要**。
- **MLP**：早期步浅层计算更多；深层在早期步、浅层在后期步稀疏更低。
- 方法能**跨所有步重新分配计算**，减少对全计算步的依赖；额外资源分配给 MLP（因其能纠正缓存引入的误差）。

## 🔑 关键结论

1. **端到端学习稀疏分配** 优于手工设定和搜索方法（GA/Random），且训练成本更低（4h vs 16h）。
2. **两阶段训练** 通过 warm-start 注入 full-step 先验并逐步淡化，消除了硬性 full-step 依赖。
3. **代价矩阵与 token 长度解耦**，实现低分辨率训练→高分辨率推理的迁移。
4. **FID 超越原模型** 的反直觉结果表明：学习到的稀疏调度可加速生成分布收敛、提升保真度，token 稀疏化兼具"压缩"与"正则化"双重作用。
5. 方法**通用性强**：跨 DiT、PixArt-α、FLUX、Wan2.1 四类架构，涵盖文生图/类条件生成/文生视频，且能加速已蒸馏模型。

### 讨论

### Q9: Token 选择器公式 (5) 与"四个准则"是什么关系？

公式 (5) `S(x̂_i) = B(Σ_{q=1}^{Q} λ_q · s_q(x̂_i))` 是**通用抽象模板**：若干标量信号加权求和，再经可选算子 B 处理。附录给出**具体实例化**（取 Q=3）：

```
S(x̂_i) = B( λ₁·s₁(x̂_i) + λ₂·s₂(x̂_i) + λ₃·s₃(x̂_i) )
```

- `s₁`(self-attn influence)、`s₂`(cross-attn focus)、`s₃`(cache-reuse frequency) 是求和里的**三个加权信号**；
- `B`(spatial bonus) 是作用于求和结果的**后处理算子**（k×k 邻域内最高分者加 `λ₄`），**不是第四个求和项**。

**关键澄清**：所谓"四个准则"严格说不是"四项加权"，而是"三项加权 + 一个空间加成修饰"。main text 明确 B "optional"，印证它是修饰算子而非加权和项。因此 `λ` 系数只有三个（`λ₁,λ₂,λ₃`）用于加权，`λ₄` 是 B 的加成幅度，性质不同。

### Q10: 可学习稀疏代价预测器中 T、L 分别是什么？

- **T = 去噪步数**（timesteps）：PixArt-α T=20、DiT T=50、Wan2.1 T=25、FLUX T=4。
- **L = 可独立分配稀疏值的子层数**（**不是 block 数**）：
  - PixArt-α / Wan2.1：每个 block 含 SA、CA、MLP 三层各自独立分配 → `L = 3 × block数`；
  - DiT：无 CA → 去掉 CA 对应预测器；
  - FLUX：含 image MLP、text MLP、standard MLP，各自独立分配。
- 代价矩阵维度 `(T×L)×|S|`，与 token 序列长度 N 无关 → 可跨分辨率迁移。

### Q11: 动态规划求解器的目标是得到每一层要保留的 token 数量吗？

是的。DP 在全局稀疏约束 R 下最小化累计代价，输出每个 (层 l, 步 t) 的最优稀疏率 `s_{l,t} ∈ S`。每个稀疏率 s 直接对应保留 token 数 `K = s × N`（如 N=256、s=0.5 → K=128）。所以 DP 的产出就是"每层每步保留多少 token"（等价于稀疏率）。

补充：DP 仅在**训练时**运行（约 30 秒），求出最优 mask 后预计算；**推理时直接用预计算 mask，零求解开销**。

### Q12: 整体流程是否=learnable 得到每层删减量→按重要性删减→student→蒸馏？是全量微调吗？

理解大体正确，但有两个**关键澄清**：

1. **不是权重剪枝，是 token 特征缓存**。token 不是被"删减/移除"，而是"复用缓存特征"（跳过重算，见公式 3、4）。模型权重全程不变，student 与 teacher 的唯一区别是：哪些 token 在哪些层/步复用缓存 vs 重新计算。所以不存在"剪枝后的权重"。

2. **不是全量微调**。可训练参数**只有代价预测器 C**（尺寸 `(T×L)×|S|`，仅几千个参数），**模型权重全程冻结**。LPIPS"蒸馏"是训练 C 的目标信号，而非微调模型权重。梯度路径：`LPIPS loss → student 输出 → student 前向图（含冻结权重）→ mask →（经 STE）→ C`；teacher 仅提供目标 `x₀`（detached，不回传）。4~10 GPU·h 的训练成本也印证了"只训练轻量调度器"。

3. **student 与 C 共同演化**：student 不是预先得到的固定模型，而是随 C 更新而变化（每次迭代 C 变 → 调度变 → student 行为变）。训练结束得到最终 C → 最终缓存调度 → student（= 原模型 + 调度）。

**精确流程**：学习代价矩阵 C → DP 求每层每步稀疏率（保留 token 数）→ token 选择器按重要性分数决定**哪些** token 复用 → student（冻结权重的原模型 + 动态缓存）多步采样 → LPIPS 蒸馏 loss 训练 C（经 STE）。

### Q13: token 不是一维序列吗？为什么 token 选择器有 k×k 邻域？

token 在计算时确实是一维序列 `X ∈ ℝ^{N×D}`，但它们**对应图像的 2D 空间 patch 网格**（如 256×256 图像按 patch 切分后排成 H×W 网格，仅在序列里展平成 1D）。

**k×k 邻域在这个 2D 空间网格上定义**：对每个 token，检查它在 2D 图像网格中 k×k 邻域内是否分数最高，若是则加 `λ₄`（PixArt-α k=4，DiT k=2）。

**为什么需要**：若只按分数取 top-K，重要 token 可能在空间上聚集（如主体物体区域），导致其它区域全用陈旧缓存 → 局部伪影。空间加成鼓励被重算 token **均匀覆盖**整个画面。

### Q14: 代价预测器 C 是什么模型？输入和输出是什么？

**C 不是神经网络，就是一个可学习参数表**（类似 embedding 查找表），形状 `(T×L)×|S|`。

- **输入**：无（无条件输入特征）。概念上"输入"是索引 `(t, l, s)`，查表得到 `C[(t,l),s]`。
- **输出**：代价矩阵 C 本身（归一化后）。每个标量 `C_{(t,l),s}` 表示"层 l、步 t 用稀疏率 s 的代价"。
- **训练**：直接对这些参数做 SGD，梯度来自 LPIPS loss 经 STE 回传。

叫"predictor"有点名不副实——它就是一张被端到端优化的代价表。这解释了参数量极小（几千个）、训练只需 4~10 GPU·h。

### Q15: "student 与 C 共同演化"与"模型权重全程冻结"矛盾吗？

不矛盾，"演化"**不指权重变化**，而指**缓存调度策略变化**：

- 模型权重：**全程冻结，永不更新**。
- C：每次迭代由 SGD 更新 → DP 重新求最优分配 → 缓存 mask 改变。
- student 的"行为"（哪些 token 复用/重算）随 C 变化而变化。

所以 student = (冻结权重, 随 C 演化的调度)。变的是调度策略，不是权重。准确表述应为"**student 的缓存策略随 C 训练而演化，权重始终冻结**"。

### Q16: Pruned token 是"拿掉计算再拼回"还是"值更新别的 token"？

**两者都不准确，且绝对不是"拿掉再拼回"**。这是 token **特征缓存**（feature caching），不是 token **丢弃**（token dropping，如 DyDiT）。机制见公式 3、4：

1. **序列长度始终为 N，token 不被移除**，不存在"拿掉→精简计算→拼回"。

2. **缓存 token 留在序列里，输出用旧缓存值**：
   ```
   F(x̂_i) = γ_i·f(x̂_i) + (1-γ_i)·C(x̂_i)
   缓存 token (γ=0): F = C(x̂_i)   ← 直接用缓存，跳过层计算 f
   重算 token (γ=1): F = f(x̂_i)    ← 正常过层，并更新缓存 C(x̂_i)←F
   ```

3. **缓存 token 自身值不更新**（输出=旧缓存），但其旧特征会**影响别的 token**：self-attention 中缓存 token 仍作为 K/V 参与，重算 token 会注意到它们的（陈旧）特征。**这正是 `s₁`(self-attention influence) 的存在意义**——高影响力 token 若缓存旧值，误差传播给他人，故须优先重算。

4. **缓存 token 何时更新**：只有当它在后续某步/层被选入 `I_Compute` 时才重算并刷新该层缓存。`s₃`(cache reuse frequency) 跟踪自上次重算以来被复用次数 `n_i`——复用越多越陈旧，越该重算。

5. **跨层传播**：缓存 token 的输出（旧缓存值）成为下一层该 token 的输入，陈旧特征沿层向前传播，直到被重算刷新。

**一句话**：token 不被删除，而是"带着旧特征留在序列里继续参与计算（尤其 attention 的 K/V），自身不刷新，直到被调度重算时才更新"。

### Q17: "代价"如何传输到模型中参与训练？

**核心澄清：代价 C 本身不进入模型前向计算，模型永远"看不到"代价值。** C 只通过 DP 决定 mask，mask 才是模型用的东西。

**前向**（C 只在第一步出现）：
```
C (参数表)
  → DP 求解：全局约束 R 下选每 (t,l) 最优稀疏率 s*_{t,l}   [离散、不可微]
  → 按 s*×N 得保留数 K，token 选择器按重要性取 top-K
  → 构造二值 mask M \in {0,1}^N (1=重算, 0=缓存)             [离散、不可微]
  → student 用 M 做缓存前向（模型只用 M，不用 C）
  → 输出 x₀' → LPIPS loss
```

**反向**（梯度经 STE 回到 C）：
```
LPIPS loss → ∂L/∂x₀' → student 前向图 → ∂L/∂M (对 mask 的梯度)
  → M 和 "C→DP→M" 都不可微
  → STE：反向时"假装"离散化是恒等映射，把 ∂L/∂M 直接传给 C
  → C 收到近似梯度，SGD 更新
```

**直观**：梯度告诉"若调整 mask 能否降 loss"；STE 把信号归因到"被选中候选 s* 的代价"，于是降低/抬高 `C_{(t,l),s*}`，使 DP 下次更倾向选更优分配。**C 不参与前向数值计算，它是"调度参数"，只在"决定 mask"这一环出现，梯度经 STE 从 mask 回传。**

### Q18: S 是整型数吗？|S| 怎么确定？数字越大 pruned token 越多？

需纠正几处理解：

1. **S 不是整型数，是候选集合**。`S = {0, 0.25, 0.5, 0.75, 1.0}`，即候选保留率的离散选项。`|S|` 才是整数（集合大小，这里 =5）。

2. **s ∈ S 是"保留(重算)比例"，不是"剪枝比例"**。论文"sparsity rate"措辞较松，但明确写道 `S={0,0.25,...}` 对应"retaining {0,64,128,192,256} tokens"。所以：
   - **s 越大 → 重算越多 → pruned(缓存)越少**；
   - s=1 → 全部重算（不缓存）；s=0 → 全部缓存（最大剪枝）。

3. **|S| 由候选间隔决定**（超参数）：间隔 0.25 → |S|=5；间隔 0.125 → |S|=9。消融显示**间隔 0.25（|S|=5）最优**；太细（0.1, |S|=11）收敛慢，太粗（1.0, |S|=2）选择太少。

4. **整体流程理解正确**：C `(T×L×|S|)` + DP → 确定每步每层保留率 s* → 构造 mask → 缓存/重算 → 算 loss。两处措辞修正：(1) 是"缓存"非"删减"（token 不删除）；(2) loss 训练 **C**（非模型权重）。

5. **C 与 |S| 的关系**：对每个 (t,l)，C 存 |S| 个代价值（每个候选率一个）；DP 从这 |S| 个里挑一个使总代价最小且满足全局约束。C 编码"每个候选率在每层每步的代价"，DP 用它做组合优化。

### Q19: 是准备了多个候选集合 S1/S2 吗？每个 S 长度要=T×L 吗？

**不是。只有一个共享候选集 S = {0, 0.25, 0.5, 0.75, 1.0}，所有 (t,l) 位置都从这同一个 S 里选。**

- **|S|=5 是候选数**（5 个候选保留率），**不是 T×L**。
- **T×L 是"位置数"**：每个位置（一个 (步,层) 组合）选一个 s。
- **C 形状 (T×L)×|S|**：想象成一张 `(T×L) 行 × |S| 列` 表格——每行一个位置，每列一个候选率，格子里的值是"该位置选该候选的代价"。DP 从每行选一格，使总代价最小且满足全局约束 R。

所以是"一个 S + 一张代价表"，不是多个 S。

### Q20: Distillation 每次前向都算 DP 吗？为什么？

**用户的推理正确**：C 每次更新 → 最优分配会变 → 需重新 DP。**DP 不是"和 loss 无关"，而是 C 影响 mask、进而影响 loss 的唯一桥梁**——没有重新 DP，更新的 C 无法传递到 mask，梯度失去意义。

工程上：单次 DP 约 30s，总训练 4h。若每个迭代都跑 DP 会超时，故**实际很可能是周期性重算**（每若干迭代/每 epoch 重算得新 mask，中间用固定 mask + STE 更新 C），论文未明确频率。推理时完全不跑 DP，用预计算 mask。

### Q21: 心智模型修正——s 可训练？越往下递增？太难训练了吧？

需修正四处理解：

1. **"s 可训练"不准确**。可训练的是**代价 C**；s* 是 DP 的**输出**（离散选择），不直接训练。C 经 STE+SGD 更新，s* 由 DP 从 C 推导。优化的是"代价标定"，不是直接优化 s。

2. **"越往下 s 递增"是错误假设**。学习到的 s* 模式**非单调**、依赖层类型（见 Figure 3）：SA 早期步+浅层稀疏高；CA 后期步+深层稀疏低（文本语义在初始层重要）；MLP 分布又不同。**数据驱动**学出，非手工递增。

3. **"s 对应 loss"不准确**。C 不是"该稀疏度造成的 loss 值"，而是经 LPIPS loss 端到端优化出的**代理代价（surrogate）**。无闭式表达，是学出来的标量，"恰好"在优化后反映各选择好坏。

4. **"找最好 loss 组合"** → DP 找"最小总**代价**组合"（在全局约束 R 下），非直接最小化 loss。


### Q22: C 是 T×L×|S| 矩阵？<t,l> 选 s 得到的值是 loss？是"在不同 metric 下发现状态图"？

- **C 是 T×L×|S| 矩阵** ✓。
- **"该值是 <t,l> 选 s 带来的 loss"——不准确**。该值是经 LPIPS 端到端学出的**代理代价（surrogate cost）**，非真实 loss 值，无闭式表达。直觉上可视为"代价状态图"，但严格说是 surrogate。
- **"在不同 pruning metric 下发现这个状态图"——需纠正**。C 与 importance metric **正交**：C 学"多少 token 重算"，metric 学"哪些 token 重算"。Table 4 证明不同 metric（Norm/Similarity/Attention）下 C 的增益一致，说明 C 独立于 metric，并非"在不同 metric 下发现状态图"。
- "再通过 DP 和给定稀疏要求做 token pruning"——对，但 "pruning" 应为 "caching"（token 不删除）。

### Q23: 训练这个"状态图"用了多少训练样本？

**10,000 个样本，且不用图像数据**，只用文本/类别条件：

| 模型 | 训练样本 | 来源 |
|------|---------|------|
| PixArt-α / FLUX | 10,000 captions | COCO train |
| DiT-XL/2 | 10,000 class indices | ImageNet train |
| Wan2.1 | 10,000 captions | WebVid-10M |

不与评测集重叠。训练时用这些 prompt 跑扩散采样，与 teacher 输出比 LPIPS。样本量小且无需图像，是方法轻量的又一体现。
