# Partition Generative Modeling: Masked Modeling Without Masks

> **来源**: arXiv:2505.18883  
> **作者**: Justin Deschenaux, Lan Tran, Caglar Gulcehre (EPFL)  
> **会议**: ICLR 2026  
> **核心主题**: 用"分组预测"替代 `[MASK]` 机制，实现高效的并行生成

---

## 一、核心问题

### 1.1 背景对比

| 特性 | 自回归模型 (ARM) | 掩码生成模型 (MGM) |
|------|-----------------|-------------------|
| 生成方式 | 逐 token 顺序生成 | 并行、任意顺序生成 |
| 推理效率 | 只处理已生成的 clean token | **每步都需处理全序列**，含 `[MASK]` token |
| 典型代表 | GPT 系列 | MaskGIT, MDLM |

### 1.2 MGM 的推理瓶颈

MGM 在推理时的核心问题：
- **每步都要处理完整序列**长度 L（包括大量 `[MASK]` token），计算量与序列长度成正比
- `[MASK]` token 本身**不携带任何信息**，却占据了大量计算资源
- 这限制了 MGM 在大规模实时场景和测试时计算扩展（test-time compute scaling）中的实用性

### 1.3 现有方案的局限性

| 方法 | 思路 | 局限 |
|------|------|------|
| 每步解码更多 token | 提高吞吐量 | 样本质量下降 |
| 蒸馏 (Distillation) | 减少采样步数 | 每步计算量不变，影响多样性 |
| Block Diffusion | 分块生成 + KV-cache | **牺牲了任意顺序生成**的能力 |

**核心矛盾**：没有方法能在保持 MGM 并行任意序生成特性的同时，让单个采样步骤更轻量。

## 二、核心方法：Partition Generative Models (PGM)

### 2.1 核心思想：用"分组"替代"掩码"

```
传统 MGM:  [clean] [MASK] [MASK] [clean] [MASK]  ← 处理全序列含无用 [MASK]
PGM:       [Group 0] ↔ [Group 1]                  ← 两组互不注意，互为条件
```

**关键机制**：
1. 将 token 分成**两个互不相交的组**（Group 0 和 Group 1）
2. 使用**组内注意力**（group-wise attention）确保两组之间**无信息流动**
3. 模型学习从 Group 0 预测 Group 1，反之亦然
4. **完全消除 `[MASK]` token**

### 2.2 与 MDLM 的数学联系

PGM **直接扩展**了 MGM 范式：

- **训练时**：MDLM 用 `α_t` 比例的 clean token，PGM 用 `α_t` 比例的 Group 0 token（角色对应）
- **损失函数**：PGM 在一次前向传播中**同时评估两个互补的掩码率**，产生两个互补的训练信号
- **权重**：Group 1 token 用 `w(t)` 加权，Group 0 token 用 `w(1-t)` 加权

```
L_PGM = E[ w^PGM(g, t) · CE(θ(x; g; t), x) ]

w^PGM(g, t)_i = w(t)     if g_i = 0 (Group 1 被预测)
                w(1-t)   if g_i = 1 (Group 0 被预测)
```

### 2.3 方差减少

- MGM 只在 masked token 上计算损失，PGM 在**每个位置都计算损失**
- 单条序列产生**两个互补的梯度贡献**
- 降低梯度方差，提升验证困惑度（LM1B 上降低 1.95）

## 三、Partition Transformer 架构

### 3.1 整体结构

```
输入序列
  │
  ▼
┌─────────────┐
│  Encoder     │  组内自注意力（两组互不注意）
│  (Group-wise │  ↓
│   Self-Attn) │  GroupSwap: 跨组注意力
└─────────────┘  ↓
  │            ┌─────────────┐
  └────────────►│  Decoder     │  组内交叉注意力（无自注意力！）
                │  (Cross-Attn)│  → 只在待解码位置计算预测
                └─────────────┘
```

### 3.2 三大组件

#### (A) Encoder — 组内自注意力
- 标准双向 Transformer block 的变体
- **不同组的 token 不参与彼此的注意力计算**
- 信息保持在组内本地化

#### (B) GroupSwap — 跨组信息交换
这是 PGM 的**核心创新组件**，解决了一个关键矛盾：

> Encoder 中 Group 0 的表示只依赖 Group 0，但预测 Group 0 位置的 token 需要依赖 Group 1

**GroupSwap 解决此问题的方法**：使用交叉注意力（cross-attention）将每个位置的表示路由到对立组。

**Query 初始化的两种方式**：

| 方式 | 描述 | 效果 |
|------|------|------|
| **数据无关 (Data-Independent)** | 可学习向量 + 正弦位置编码 + LN + 线性投影 | 更简单，效果相当 |
| **数据相关 (Data-Dependent)** | 先对每组做聚合（logsumexp/mean），再加入查询 | 利用组级统计信息 |

#### (C) Decoder — 组内交叉注意力
- **只有交叉注意力层，没有自注意力层**
- Keys/Values 来自 Encoder 输出
- Queries 来自 GroupSwap 输出
- 这使得推理时可以**只在需要解码的位置计算预测**

### 3.3 架构设计的核心洞察

> **没有自注意力 = 高效生成**

Decoder 中移除自注意力后，推理时只需计算待解码位置的预测，不需要处理全序列。这与 ARM 的 KV-cache 原理类似，但适用于并行生成场景。

## 四、训练与推理流程

### 4.1 训练流程

1. 采样 `t ~ U[0, 1]`
2. 每个 token 以 `p_t = 1 - α_t` 概率分配到 Group 1
3. Encoder 做组内自注意力
4. GroupSwap 交换跨组信息
5. Decoder 做组内交叉注意力，预测对立组的 token
6. 在**所有位置**计算加权交叉熵损失

### 4.2 推理流程

```
初始: 只有 BOS token
循环 K 步:
  1. 选择 k 个位置进行解码
  2. 将 clean token 输入 Encoder（只处理 clean token！）
  3. GroupSwap 交换信息
  4. Decoder 只在选定位置计算预测
  5. 将解码的 token 加入 clean 集合
```

**关键优势**：推理时的序列长度随步数**递增**（类似 ARM），而非固定为全长（类似 MGM）。

### 4.3 采样策略

| 采样器 | 适用场景 | 描述 |
|--------|---------|------|
| 固定步数采样 | 文本（MDLM 兼容） | 每步解码 k 个 token |
| 置信度采样 | 图像（MaskGIT 兼容） | 按预测置信度选择位置 |
| Halton 采样 | 图像（最佳） | 用低差异序列均匀覆盖空间 |

## 五、实验结果

### 5.1 语言建模

**数据集**: LM1B (ctx=128), OpenWebText (ctx=1024)

| 指标 | MDLM | PGM (最佳) | 提升 |
|------|------|-----------|------|
| LM1B Val. PPL | 27.67 | **26.80** (6/6) | -0.87 |
| LM1B Val. PPL (Compl. Masking) | 25.72 | - | - |
| OWT Val. PPL | 23.07 | **21.43** (6/6, dim=1024) | -1.64 |
| **吞吐量 (LM1B)** | 1,082 tok/s | **1,931 tok/s** | **1.78×** |
| **吞吐量 (OWT)** | 1,043 tok/s | **5,586 tok/s** | **5.35×** |

**下游任务准确率**：PGM 在 8 个任务中的 6 个上超越 MDLM，表明**更快的推理速度不牺牲下游性能**。

**蒸馏后**：使用 SDTT 蒸馏 + nucleus sampling (p=0.9)，PGM 仍比 MDLM 快约 4.6×，且生成质量相当。

### 5.2 图像建模

**数据集**: ImageNet256 (VQGAN, 1024 tokens)

| 模型 | 步数 | FID | IS | 吞吐量 (img/s) | 速度比 |
|------|------|-----|-----|---------------|--------|
| MaskGIT | 32 | **5.35** | 267 | 1.05 | 1× |
| PGM 12/12 | 32 | 5.54 | 264 | **7.93** | **7.5×** |
| PGM 12/12 | 64 | **4.56** | 219 | 4.12 | **3.9×** |

**关键发现**：
- 用 Halton 采样器时，PGM 32 步达到与 MaskGIT 相当的 FID，**快 7.5 倍**
- 增加到 64 步，FID 提升至 4.56，仍快 **3.9 倍**
- PGM 12/12（编码器/解码器各 12 层）优于 14/10（不平衡），说明**均衡的层分配更优**

### 5.3 互补掩码的消融实验

| 数据集 | MDLM | MDLM+互补掩码 | PGM |
|--------|------|--------------|-----|
| LM1B (1M步) | 27.67 | **25.72** | 26.80 |
| OWT (1M步) | 23.07 | 22.98 | **21.43** |

- 互补掩码策略在 LM1B 上有显著改善，但在 OWT 上改善较小
- PGM 架构 + 互补掩码的组合在两个数据集上都表现出色
- 在短上下文（128 tokens）下，互补掩码效果更显著

### 5.4 训练效率

| 数据集 | MDLM 训练吞吐 | PGM 训练吞吐 | 比率 |
|--------|--------------|-------------|------|
| LM1B | 715 seq/s | 794 seq/s | 1.11× |
| OWT | 81 seq/s | 63 seq/s | 0.78× |

- LM1B 上 PGM 训练开销可忽略
- OWT 上 PGM 约为 MDLM 的 75% 训练效率
- **推理时 PGM 快 5×，训练时 PGM 慢约 25%** — 这是一个合理的权衡

### 5.5 长上下文泛化

在 4096 token 上下文长度下，PGM 吞吐量是 MDLM 的 **4.2-4.3×**，表明 PGM 在长序列场景下优势更大。

## 六、关键贡献总结

1. **方法创新**：提出 Partition Generative Models，用分组替代掩码，完全消除 `[MASK]` token
2. **架构创新**：设计 Partition Transformer，通过组内注意力 + GroupSwap + 无自注意力解码器实现高效推理
3. **训练改进**：互补掩码策略降低梯度方差，提高验证困惑度（1.95 点）
4. **效率提升**：文本 5-5.5× 加速，图像 7.5× 加速
5. **兼容性**：与现有 MGM 采样器、CFG、SDTT 蒸馏方法完全兼容

---

## 七、局限性与未来方向

### 7.1 当前局限
- **训练效率**：PGM 训练比 MDLM 慢约 25%（因使用 `torch.sdpa` 密集掩码实现）
- **参数需求**：在 OWT 上达到相同验证困惑度需要略多的参数
- **架构开销**：GroupSwap 层增加了模型复杂度
- **多模态扩展**：尚未在多模态场景中验证

### 7.2 未来方向
- 利用 PGM 的**块对角注意力模式**开发高效 kernel（重新排列 token 后，注意力矩阵变为块对角）
- 设计专门针对 PGM 的蒸馏策略
- 扩展到多模态场景
- 探索在代码生成和推理等需要 test-time scaling 的领域

## 八、个人思考与理解

### 8.1 为什么 PGM 有效？

**核心洞察**：MGM 的低效来自于 `[MASK]` token 的"空转"。PGM 通过将"掩码"替换为"分组"，让每个 token 都有明确的角色（预测/被预测），从而实现了：

1. **推理时变短序列**：只处理 clean token，类似 ARM 的增量处理
2. **训练时双倍监督**：每个样本产生两个互补的训练信号
3. **数学等价性**：PGM 的训练目标是 MDLM 目标的自然扩展

### 8.2 与 ARM 和 MGM 的关系

```
ARM:  x₁ → x₂ → x₃ → ... → x_L   (顺序依赖，每步处理1个token)
MGM:  [M,M,M,...,M] → 逐步去噪    (并行但每步处理全序列)
PGM:  G₁ ↔ G₂                    (并行+只处理clean token)
```

PGM 取了两家之长：
- 从 ARM 处借鉴了**增量处理 clean token** 的思想
- 从 MGM 处继承了**并行任意序生成**的能力

### 8.3 实际应用价值

- **实时生成**：推理速度提升 5-7.5×，使 MGM 类模型可用于实时场景
- **Test-time compute scaling**：PGM 天然适合 test-time compute 扩展，因为每步计算更轻量
- **代码/推理**：论文特别提到 PGM 在编码和推理任务上的潜力，这些任务受益于 test-time scaling
- **即插即用**：可直接替换现有 MGM 架构中的 backbone，无需修改上层采样/蒸馏逻辑

### 8.4 开放问题

1. **GroupSwap 的替代方案**：是否存在更高效的跨组信息交换机制？
2. **动态分组**：当前是随机分组，能否用学习到的分组策略进一步提升效果？
3. **与 KV-cache 结合**：能否将 PGM 的增量处理特性与因果注意力结合，实现更极致的推理效率？
4. **多模态**：在文本-图像、视频等多模态生成中，分组策略是否依然有效？
